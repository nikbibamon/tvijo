# tvijor · игровой продакшен Tvijo

Версия 0.1.0 запускает проверку Академии и готовит задание для работы Codex на следующем игровом релизе. Контекст продукта, адреса двух игр и промпт для следующего чата находятся в [START-HERE.md](START-HERE.md).

## Запустить на ВМ

Рабочий каталог в репозитории `nikbibamon/tvijo` — `games/crew-academy`. В распакованном пакете Sites это его корень. Для полного прогона нужны Node 24+, Python 3.11+, FastAPI и httpx/TestClient. Если используется новая машина, подготовь окружение.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r server/requirements.txt httpx
.venv/bin/python tvijor/run.py plan pilot
.venv/bin/python tvijor/run.py run verify
.venv/bin/python tvijor/run.py run pilot
```

В уже подготовленном окружении достаточно `python3 tvijor/run.py run verify`. Для проверки самого оркестратора выполни `python3 -m unittest discover -s tvijor/tests`. Игра локально запускается через `npm run dev`. Собранный для Sites Worker создаётся командой `npm run build`.

Каждый прогон получает новый каталог в `var/tvijor/`. На экране появляется точный путь. В каталоге лежат автономная страница `index.html` с раскрывающимися контрактами, текстами скиллов и журналами, машинная квитанция `run.json` и журналы проверок. Можно задать другой родительский каталог флагом `--out`. Работай в отдельной копии кандидата, поскольку штатный сборщик пишет файл в `dist/`.

## Пайплайны и исполнители

| Процесс | Что выполняет | Когда закончен |
|---|---|---|
| `verify` | Сверяет графику, зависимости поручений и досягаемость, запускает тесты Node и FastAPI, собирает Worker и обращается к готовому обработчику | Проверки прошли, в квитанции записаны отпечаток исходников и SHA-256 сборки |
| `pilot` | Формирует бриф и задание для Codex, принимает результат разработки, выполняет проверки кандидата и считает результаты игровых наблюдений | Для той же версии есть результаты реальных первых попыток и выполнен критерий пилота |

Реестр `studio.json` определяет роли, зависимости, способ выполнения, вход и результат каждого этапа. В `skills/` живут четыре проектные инструкции по арту, механикам, пилоту и выпуску. Инструкция задаёт способ работы, роль назначает исполнителя, DAG определяет очередность. Независимые этапы остаются доступными, если один из соседних требует помощи. Текущий раннер исполняет готовые локальные этапы последовательно. Разработку отдаёт внешнему Codex в `job.json`. Вызовы модели, чтение учётных данных, отправка задания в RemDesk и публикация не входят в команду проверки.

## Продолжить кандидат

1. Запусти `run pilot`. Прочти `TASK.md`. Для передачи Codex используй соседний `job.json` с ролью и ожидаемыми результатами.
2. После изменения игры выполни `run pilot` ещё раз. Раннер сам впишет SHA-256 игровых исходников в поле `source`. Скопируй из новой папки файл `evidence-template.json` в отдельный рабочий `evidence.json`.
3. Заполни `candidate` объектом с коротким `summary` и массивом `paths` реально изменённых игровых файлов относительно версии 7. Укажи пути из корня игры, например `web/app.js`, если этот файл изменён. Раннер проверит их по рабочему дереву.
4. В массив `sessions` заноси реальные наблюдения. Формат одной записи приведён ниже. Значения в примере только показывают поля. Для проигранной попытки поставь `captured: false` и время выхода.

```json
{"device":"iphone-safari","input":"touch","seconds":142,"captured":true,"helped":false}
```

Допустимые устройства — `iphone-safari`, `android-chrome`, `desktop`, `mobile-emulator`. Способы ввода — `touch`, `keyboard`, `voice`. Указывай основной способ ввода. Храни по одной записи на первую попытку одного человека. Эмуляция учитывается отдельным числом. Начни с пяти человек и обязательно включи хотя бы одного игрока на настоящем телефоне.

5. Выполни `python3 tvijor/run.py run pilot --evidence evidence.json`. Новый прогон проверит все этапы и вернёт итог. У формы есть отпечатки игры и контракта tvijor. Изменение игровых файлов или контракта делает старую форму неприменимой. Запись каждого прогона хранит также отдельный отпечаток самого tvijor.

| Код выхода | Результат |
|---|---|
| 0 | Все этапы выбранного процесса прошли |
| 1 | Ошибка команды, сборки, формата или источника данных |
| 2 | Процесс ожидает результат разработчика или игровые наблюдения |
| 3 | Наблюдений достаточно, игровой критерий требует доработки |

Сверить принятый выпуск можно по [квитанции ВМ](acceptance-v7.json). В ней зафиксированы проверки графики, выборка миров и ответы встроенного обработчика. Проверка доступности настоящего адреса на сервере выполняется отдельно.
